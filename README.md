# LJHskill 电商老家伙工具箱

## 我们是谁

我们是一家专注内容电商增长的咨询公司，提供线下课、咨询、内训和陪跑服务。你现在体验到的这套 skill，是我们方法论体系的一环。

我们期望始终代表中国电商最先进生产力的发展方向，所以把这套 skill 免费开源。欢迎电商从业者拿去就用，也欢迎同行一起升级迭代。

我们的目标很简单。当年马斯克为了加速可持续能源的普及，造出了 Model Y，并开源了自己的专利。致敬这样的做法，我们希望真正用 AI 的力量，帮中国电商企业做得更好，走向全球。

---

LJHskill（李解瀚森 skill），外号「电商老家伙」：第一句说清你卡在哪，第二句它带你跑对的工具。取 LJH 三个字母的谐音。

从一门约 20 万字的内容电商实操课里，把可执行的部分（诊断表、判断标准、SOP、填空模板）提炼出 19 个业务工具 + 1 个主入口，覆盖联名开品、开品、选品、价值、定位、卖点、场景、内容、验证、投放、指标诊断、算账全链路。课程正文不在本仓库，这里只有拿来就能跑的工具。

## 新手第一次用，三步走

1. **装**：打开终端，贴一条命令（下面「安装」节有）
2. **开个新会话，敲 `/ljh`**：这是主入口，会先问你卡在哪一段
3. **把你卡住的事，用一句话说给它**：比如「这个品值不值得打」「视频跑量猛但直播间没人下单」，它会带你去对的工具

也可以直接对你的 AI 说：安装 ljhskill，它自己能找到。

## 安装

### Claude Code

```bash
claude plugin marketplace add handsomeng/LJHskill
claude plugin install ljh@ljhskill
```

装 `ljh@ljhskill` 即获得 19 个业务工具 + 1 个主入口。只想单独装某一个工具时，才用类似 `claude plugin install ljh-xuanpin@ljhskill` 的命令。

### 通用安装（Codex / Claude Code）

```bash
npx -y skills add handsomeng/LJHskill -g --all
```

## 典型主线

```text
开品原点
    ↓
可行性闸门（需求、交付、合规、供应链、suanzhang 预估账）
    ↓
价值与定位
    ↓
场景与内容假设
    ↓
KOC 或素材验证
    ↓
对齐、内容执行与放大
    ↓
suanzhang 实际总账与经营复盘
```

## 怎么用这套东西

**场景一，新手入局**：还没有成型的品，只有想法、工厂提案或竞品线索，从 `/ljh-kaipin` 把概念立住。已经有候选品时，用 `/ljh-xuanpin` 过五个可行性闸门，预估账由 `/ljh-suanzhang` 的预估模式完成。进入验证后再走价值、定位、场景、KOC 或素材验证、内容与放大，实跑数据回来后用实算模式收口。也可以直接说带我从头打这个品，主入口会按这条链陪跑。

**场景二，已经在跑的盘子**：品在跑了，但哪里疼就查哪里。千川掉量用 `/ljh-qianchuan`，GMV、转化、ROI、新客、复购或内容效率波动用 `/ljh-zhibiao`，卖点被质疑或表达站不住用 `/ljh-maidian`，脚本转化不理想用 `/ljh-jiaoben`。口碑或退货问题可以先用 `/ljh-zhibiao` 诊断指标影响、用 `/ljh-suanzhang` 诊断利润影响，具体治理不在当前工具箱范围内。如果同时在做小红书图文种草，一条笔记卖爆了想复刻，用 `/ljh-xhs` 拆到能迁移的机制层面，不用从头走一遍，整套工具随时单独调用。

**场景三，只拿一个工具用**：不想装全套也可以。19 个业务工具每个都能单独安装、单独跑，互不依赖，拿走你需要的那一个就够。

**场景四，给团队用**：团队装同一套，各自按自己的岗位取用。

- 编导：用 `/ljh-jiaoben` 评审脚本，用 `/ljh-yinzi` 拆内容因子
- 投手：用 `/ljh-qianchuan` 排查千川问题
- 业务负责人：用 `/ljh-zhibiao` 诊断关键指标波动，用 `/ljh-suanzhang` 核对经营总账
- 商品运营：用 `/ljh-shangxiang` 制定商详页策略，安排逐屏承接、证据和风险
- 商务：用 `/ljh-daren` 选号，用 `/ljh-brief` 准备主播合作 Brief
- 产品：用 `/ljh-kaipin` 把开品原点做成可评审概念，用 `/ljh-jiazhi` 把价值想全
- 操盘手：用 `/ljh-xuanpin` 过可行性闸门，用 `/ljh-suanzhang` 把总账算清楚

## 三轴状态协议

核心经营工具用三条独立状态传递结论：字段决策状态为「已确认、待确认、修改建议」；证据状态为「已核验、待核验、无证据、已过期、不适用」；验证结果为「验证通过、信号偏弱、验证失败、未验证」。进入验证只代表具备测试条件，验证结果仍是「未验证」。下游保留上游状态，任何改写先列为「修改建议」。

## 交付物字段所有权

内容链路按所有权分工：`/ljh-jiazhi` 生产价值候选，`/ljh-dingwei` 生产标准定位、标准人群和心智句，`/ljh-maidian` 评审卖点表达、独特性与证据缺口，`/ljh-duiqi` 负责翻译，`/ljh-brief` 负责主播合作整理，`/ljh-shangxiang` 负责页面编排，`/ljh-jiaoben` 负责脚本诊断，`/ljh` 只路由和传递。

下游发现问题时保留原字段，新增修改建议、理由、回退所有者和确认动作。字段所有者确认前，标准字段保持不变。卖点评审通过只覆盖本轮表达与独特性判断，不代表市场验证通过或合规批准。

## 档案与陪跑

档案是一份 `ljh-档案/品牌档案.md`，存在你当前工作目录下，记品基本盘、人群、卖点验证状态和历次结论时间线。任何工具跑完交付，都会问一句要不要建档；建了之后，下一个工具会先读档案，档案里有的信息不再重复问，只问增量。

陪跑是主入口 `/ljh` 的第三种模式，一句「带我从头打这个品」就能触发，会带你按开品或选品到算账的完整链路一环一环走，每环结束停下来问你要不要继续。还没有成型的品时，陪跑从 `/ljh-kaipin` 起；已经有候选品时，从 `/ljh-xuanpin` 起。

不想要档案完全没问题，明说不用即可，单独装某一个工具照样能用，不受影响。

## 更新机制与隐私

每个 Skill 都自带更新检查器。业务交付完成后，环境允许执行脚本时，它每 48 小时最多读取一次 GitHub raw 的 `release.json`，发现新版本才提示；同一版本 7 天后仍未更新可以再次提示。检查只提醒，不自动安装。

检查器只读取版本、发布时间、摘要和 README 更新入口，不发送项目内容、对话内容或用户信息。网络、解析和权限异常会静默跳过，不影响业务交付。

如需关闭更新检查，设置环境变量：

```bash
export LJHSKILL_DISABLE_UPDATE_CHECK=1
```

## 给同行：怎么参与迭代

改完任何一个 skill，先跑一遍 `python3 scripts/validate.py`。修改三轴协议时，运行 `python3 scripts/sync_three_axis_protocol.py` 及其 `--check`；修改字段所有权协议时，运行 `python3 scripts/sync_field_ownership_protocol.py` 及其 `--check`。`evals/` 目录下每个工具一份回归用例，改动逻辑前先检查对应行为用例。

用这套工具跑出过真实结果的（验证成了或翻车了都算），欢迎把案例投回来：提 issue 或加 README 底部微信都行。真实案例会变成新的回归用例和判断标准，喂回工具本身。

格式校验用 `python3 scripts/validate.py`，行为回归用 `python3 scripts/run_evals.py`（需要装 Claude Code CLI，会真调用模型产生费用）。全量跑会花钱，建议只用 `--skill` 参数跑自己改过的那个 skill。
